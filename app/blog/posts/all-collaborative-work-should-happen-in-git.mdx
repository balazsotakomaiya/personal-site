there have been a few unexpected winners of the post-AI world. markdown, for instance, started to spread like wildfire. mermaid too. agents love it. likewise, git, I think, will become increasingly prevalent in and outside of software engineering.

if there's anything agents taught us, it's that everything can be expressed in code. I make presentations in code now. promo videos too. ppc ad material.

if you're a designer, you don't need figma anymore.<br />
if you're in marketing, you don't need photoshop anymore.<br />
if you're editing videos, you likely won't need after effects or vegas pro soon enough.

sure, all of these tools are super useful, but you can actually get away with not using any of them for a lot of good quality work nowadays. agents will build it for you in code.

that then begs the question: shouldn't we all be working in git?

it's always, even pre-AI, baffled me how oddly unknown git always was beyond software engineers. how unorganised work was, beyond our circles. prefixed files with "_final_final.pptx" suffixes. files lost. files scattered across hosting providers.

my suspicion in the short term is that we'll start to see more people within software teams use git, like product owners, designers, and business analysts. code won't belong to engineers anymore, nor will the repos. in the long run, I would expect to see other professions adopting git more broadly.
